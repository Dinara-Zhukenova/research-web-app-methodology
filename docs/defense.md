# Краткий план защиты

## 1. Задача — 1 минута

Приложение связано с диссертационной темой интеллектуального управления городским освещением. Оно хранит измерения напряжения, тока, мощности и освещённости и сравнивает обычный и адаптивный режимы.

## 2. Архитектура — 2 минуты

Пользователь работает с Next.js. Frontend отправляет REST-запросы в FastAPI. Backend проверяет данные через Pydantic, выполняет бизнес-логику в сервисном слое и обращается к PostgreSQL через SQLAlchemy. Схема базы изменяется миграциями Alembic.

## 3. Демонстрация — 4 минуты

Показать список, поиск, фильтр, сортировку, переход между страницами, карточку, создание, ошибку формы, редактирование и удаление. Затем открыть `/docs` и выполнить один запрос через Swagger.

## 4. Код — 2 минуты

Открыть четыре слоя модуля `measurements`, файл миграции и тесты. Показать результат pytest, Ruff и GitHub Actions.

## 5. Вывод — 1 минута

Проект создаёт воспроизводимую основу для накопления экспериментальных данных. Синтетические данные проверяют программную реализацию; научные выводы должны основываться на реальных измерениях.

## Ответы на частые вопросы

- Server Component выполняется на сервере, Client Component — в браузере и используется для интерактивности.
- Миграции фиксируют контролируемую историю изменений схемы и позволяют одинаково развернуть БД.
- В Docker `backend:8000` — сетевое имя сервиса; `localhost` внутри frontend-контейнера означал бы сам frontend.
- Pydantic отклоняет некорректные значения с кодом 422, а отсутствующие записи возвращают 404.
- Секреты находятся в локальном `.env`, который исключён из Git.
- `docker compose down -v` удаляет том PostgreSQL и все накопленные данные.
